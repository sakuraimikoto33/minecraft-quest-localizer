# 翻訳結果の保護と安全な書き込み

## 翻訳対象だけを出力

選択した翻訳対象だけをOpenAIへ送信し、安全確認を通過した翻訳文だけを翻訳先localeの対応keyへ書きます。選択外の既知quest keyは、過去の訳が出力先にあっても翻訳先localeから除外し、FTB QuestsまたはMinecraftのfallback localeを使わせます。

既存の翻訳先localeがある場合、「選択した項目の既存翻訳を再利用する」は既定でONです。原文と同じ値は未翻訳とみなし、再翻訳します。既存訳も装飾、JSON構造、Mod名、公式用語の検証を通過する場合だけ再利用します。

原文catalogにない翻訳先固有の手動keyは保持します。ただし、本ツールが所有する `mq_localizer.*` 名前空間のkeyが現行原文から消えた場合は、古い自動生成keyとして除去します。`custom.*` 等の他の名前空間は保持します。

1.20.x以前の直書きSNBTは例外です。localeで翻訳を切り替えられるよう、[原本を `quests.bak` へ保存してquestをkey化](formats-and-output.md#120x以前の直書きquest-snbt)します。

## 保護対象

OpenAIへ送る前に次を原文から分離し、応答後に個数、内容、元のテキスト範囲を検証します。

- `&a`、`§l`、`&#RRGGBB`、`&z` 等のMinecraft装飾コード
- 実改行、文字列の `\n`、空のdescription行
- `%s`、`%1$s`、`{0}`、`${name}` 等のplaceholder
- `{@pagebreak}`、`{image:...}`、既存の `{translation.key}`
- URL、command、`modid:path`、16桁quest ID
- [固有名詞辞書](terminology-protection.md)で固定したMod名・公式用語・プロジェクト参照語
- raw JSON text componentの構造、style、click / hover event

URLや `modid:path` の直後に日本語の助詞が続く正常な訳は許可し、ASCII文字の連結や原文にない保護構文の追加は拒否します。

## fragment / token protocol

実際の `__MQP_0000__` 形式tokenをモデルに直接複写させません。アプリは原文を保護token間の固定数fragmentへ分割し、tokenを `token_0000` のようなopaque keyとして扱います。

Structured Outputsによって、OpenAIからはすべてのfragmentと各tokenの出力位置だけを受け取ります。アプリ側でkey集合と位置が完全な順列であることを検証してから元のtokenを再構築し、さらに装飾、改行、技術token、固有名詞の個数と配置を検証します。これによりtoken保持をプロンプト遵守だけに依存させません。

## 装飾範囲

`&5Infuser&r` のように開始コードとresetで単純に閉じた装飾範囲は、範囲全体を1単位として同じ行内で並べ替えられます。日本語の語順へ変更しながら、開始コード、reset、固有名詞、placeholderを同じ装飾範囲に保持します。

`&aCreate a ...` のように改行・タブのない文字列の先頭から末尾まで掛かる単純な未閉鎖装飾stackは、可動tokenにせず検証後に原文と同じ先頭へ戻します。開始/resetの分断、別の改行segmentへの移動、孤立reset、複雑な未閉鎖装飾の移動は拒否します。

raw JSONの複数text componentをまたぐ固有名詞は、各componentの文字境界とstyleを保持します。既存訳の再利用時も同じ装飾範囲にあることを検証します。

## 応答の再試行とrefusal

保護復元の不一致は対象、key、原文ファイル、理由をログへ記録し、その項目だけ1度再試行します。バッチ応答の構造だけが壊れた場合は、原因項目を特定するため各項目を1件ずつ同じprotocolで再試行します。再度検証に失敗した場合はファイルを書きません。

OpenAIが明示的なrefusalを返した場合は復元エラーとみなさず、バッチを停止して不要な項目別API呼び出しを行いません。

## 日本語のUnicode検証

翻訳先が日本語の場合、原文または固定した公式用語にないゼロ幅文字等の不可視文字、無関係な文字体系、未定義・私用・置換Unicode文字がOpenAIの本文へ新規混入していないことを確認します。検出時はその1件を再試行し、再発した場合は書きません。原文由来のMinecraft glyphは保持し、日本語以外のlocaleにはこの文字体系制限を適用しません。

## atomic writeとrollback

出力は同じディレクトリの一時ファイルへ完全に書き、検証後に置き換えます。API失敗や検証失敗で途中の翻訳ファイルを残しません。分割localeの複数ファイル更新が途中で失敗した場合は、更新済みファイルを元のbyte列へ戻します。

旧版直書きSNBTは、quest原本と言語資産を別々にstagingします。`config/ftbquests` 全体はコピーもリネームもせず、初回だけ実物の `quests` を `quests.bak` へリネームして新しい `quests` を配置します。どちらかの有効化に失敗した場合は変更済み出力を元へ戻します。

## 解析後の変更検出

翻訳開始時は解析済みのquestと固有名詞辞書を再利用し、固有名詞保護資産を再走査しません。解析後の翻訳元、確認後の出力先、staging中の旧版出力が外部変更された場合は書き込みを中止します。固有名詞資産は追加、削除、更新、リンク先変更を検出し、再解析を求めます。

変更確認でJARや言語ファイルの本文を再解析せず、解析時に記録した対象一覧とファイル状態をOpenAI API呼び出し前と書き込み直前に照合します。rollback時も外部編集を検出し、その編集を上書きしません。

## 出力pathと固定上限

自動判定した出力pathの種類、拡張子、原文との衝突はOpenAI APIを呼ぶ前に再検証します。split localeでは `lang/<翻訳先locale>` 以外へ書きません。インスタンス探索でsymlink / junctionを再帰追跡せず、翻訳元や出力先が外部へ転送される場合も読み書きを拒否します。

OpenAI応答は16 MiBまでです。1件の文字列が設定したバッチ最大文字数を超える場合はAPI呼び出し前に停止します。Structured Outputs schemaは5,000 propertiesおよび110,000文字までとし、超える場合は1バッチ件数を小さくするよう案内します。
