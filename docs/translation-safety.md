# 翻訳結果の保護と安全な書き込み

## 翻訳対象だけを出力

選択した翻訳対象だけを設定したResponses APIへ送信し、安全確認を通過した翻訳文だけを翻訳先localeの対応keyへ書きます。選択外の既知quest keyは、過去の訳が出力先にあっても翻訳先localeから除外し、FTB QuestsまたはMinecraftのfallback localeを使わせます。

既存の翻訳先localeがある場合、「選択した項目の既存翻訳を再利用する」は既定でONです。原文と同じ値は未翻訳とみなし、再翻訳します。既存訳も装飾、JSON構造、Mod名、公式用語の検証を通過する場合だけ再利用します。

原文catalogにない翻訳先固有の手動keyは保持します。ただし、本ツールが所有する `mq_localizer.*` 名前空間のkeyが現行原文から消えた場合は、古い自動生成keyとして除去します。`custom.*` 等の他の名前空間は保持します。

無料トークン枠不足で途中保存を選ぶ場合、locale SNBT・分割SNBT・分割JSON5の説明文配列は、空行や再利用した訳も含めて全行が完成した配列だけを保存します。未完成配列は原文で穴埋めせず、配列全体を除外します。確認ダイアログの完成件数も、この除外後の保存可能な件数です。安全検証に失敗した応答の再試行中に無料枠が尽きた場合は、通常エラーとして保存しません。

1.20.x以前の直書きSNBTは例外です。localeで翻訳を切り替えられるよう、[原本を `quests.bak` へ保存してquestをkey化](formats-and-output.md#120x以前の直書きquest-snbt)します。

## 保護対象

翻訳APIへ送る前に次を原文から分離し、応答後に個数、内容、元のテキスト範囲を検証します。

- `&a`、`§l`、`&#RRGGBB`、`&z` 等のMinecraft装飾コード
- 実改行、文字列の `\n`、空のdescription行
- `%s`、`%1$s`、`{0}`、`${name}` 等のplaceholder
- `{@pagebreak}`、`{image:...}`、既存の `{translation.key}`
- URL、command、`modid:path`、16桁quest ID
- [固有名詞辞書](terminology-protection.md)で固定したMod名・公式用語・プロジェクト参照語
- raw JSON text componentの構造、style、click / hover event

URLや `modid:path` の直後に日本語の助詞が続く正常な訳は許可し、ASCII文字の連結や原文にない保護構文の追加は拒否します。

固有名詞の隣に原文と同じ英数字の単語がある場合、または `a`、`the`、`per` 等の短い英語の機能語が連結した場合に、省かれた空白を復元します。例えば `&eTempad&r mod` に対する `&eTempad&rMOD` は `&eTempad&r MOD` に補正できます（隣接語の大文字・小文字は区別しません）。未知の接頭辞・接尾辞や技術tokenには適用せず、装飾と固有名詞の厳密な検証は補正後も行います。補正できない連結のログには、原文用語・連結された側・隣接する英数字の短い抜粋を記録します。

原文で用語に隣接する数量は、日本語の語順で反対側へ移せます。例えば `20 Honey Treats` に対応する `Honey Treats20個` は `Honey Treats 20個` とします。`one`～`twenty` 等の小さな英語数詞と数字の対応も確認します。別の箇所の数字や変更された数量を根拠に補正しません。独立した二つの保護名同士が直接連結した場合も区切りますが、一つの名前を構成する断片は分離しません。改行・技術tokenは数量や隣接語を探す際にも越えません。

閉じた装飾内の `/ftbteams party invite <username>` 等は、引数を含むコマンド本文全体を保持します。装飾とコマンドを一つの不可分tokenにし、引数の翻訳・欠落や句読点の混入も拒否します。装飾外の説明文は翻訳対象です。

## fragment / token protocol

`0.01mB/tick` や `25,000 RF/t` 等の数値付きレート表記は、桁区切りを含む数値・単位・スラッシュをまとめて保持します。数値の一部だけが保護されることや、翻訳時の空白挿入で `/tick` 等が新たなパスとして検出されることを防ぎます。

`Mekanism__MQP_0000__の` のように、固有名詞の完全な原文表記または公式訳が対応するtokenへ直接重複した場合は、重複だけを除去します。tokenの欠落・増加、未知の接頭辞・接尾辞、空白で分かれた語、一つの名前の断片にはこの補正を適用せず、補正後も本文・固有名詞・装飾を検証します。

実際の `__MQP_0000__` 形式tokenをモデルに直接複写させません。アプリは原文を保護token間の固定数fragmentへ分割し、tokenを `token_0000` のようなopaque keyとして扱います。

Structured Outputsによって、APIからはすべてのfragmentと各tokenの出力位置だけを受け取ります。アプリ側でkey集合と位置が完全な順列であることを検証してから元のtokenを再構築し、さらに装飾、改行、技術token、固有名詞の個数と配置を検証します。これによりtoken保持をプロンプト遵守だけに依存させません。

出力fragmentの番号は日本語訳内の位置であり、同じ番号の原文fragmentを個別に翻訳する指定ではありません。一文として訳してから保護語の前後へ本文を配置するよう指示し、`Find a [token]!` → `[token]を見つけましょう！` のように先頭fragmentを空にできる例を示します。[OpenAI公式資料](https://developers.openai.com/api/docs/guides/structured-outputs#handling-mistakes)にもあるとおり、構造化出力の形式保証だけで内容の正しさは保証されません。

英語から日本語への単一行の通常本文では、文頭が「を」で始まり、文末の句点・感嘆符の後に閉じた装飾付き語句が取り残されるパターンを検出します。該当時は一文全体を再試行し、既存訳でも再利用せず再翻訳します。アプリによる語順の推測補正は行いません。この検出は一般的な日本語校正ではなく、正常な末尾ラベル・引用・複数行や独立したJSON本文断片には適用しません。

## 装飾範囲

英語の `&5The Edge of Deliverance&r` のように、同じ装飾範囲の固有名詞へ付く `a` / `an` / `the` だけが省略される訳を許可します。修飾語や所有格の欠落、名前や本文の別の色・改行への移動は許可しません。既存訳の再利用でも装飾コードと冠詞を分けて判定します。

`The &6FTB Pyramid` や `&fThe &bAE2 Guide` のように、先頭の冠詞だけが別の装飾範囲にある場合も省略できます。後続の名称本文が残ることを検証し、先頭色・名称色・コード順序は変更しません。末尾の名称を別に翻訳する場合も、その本文を復元する前提で冠詞だけの応答を検証します。動詞・修飾語の欠落や改行をまたぐ移動は許可しません。

末尾の余分なリセット（`&c本文&r.&r` の最後の `&r` 等）は削除せず、アプリ側で末尾へ固定して復元します。前の閉じた装飾範囲は文の語順に合わせて移動できます。`&z` / `§z` は前の色を引き継ぐ修飾コードではなく、FTBの虹色指定として扱います（[FTB Quests公式変更履歴](https://github.com/FTBTeam/FTB-Quests/blob/main/CHANGELOG.md#2101117)）。

`&5Infuser&r` のように開始コードとresetで単純に閉じた装飾範囲は、範囲全体を1単位として同じ行内で並べ替えられます。日本語の語順へ変更しながら、開始コード、reset、固有名詞、placeholderを同じ装飾範囲に保持します。

`&eMekanism &dFission Reactors&r` のように途中で色が変わる場合も、resetまでを一つの範囲として扱います。内部の色コード順序と各色に属する本文・固有名詞は維持します。用語と空白だけの範囲はアプリ側でまとめて保持し、名称の周囲にある動詞や所有表現などは翻訳対象に残します。

`&o説明 &cString&f!&r` のような複合装飾の末尾にある記号専用の色範囲は、終了コードと一緒にアプリ側で復元します。子の翻訳に記号範囲を開放しないため、子では許可された本文の移動が親の色範囲検証で失敗する不一致を防ぎます。記号・色コードの値と並びは維持します。

`&bStorage Bus'&r` のような所有格や、固有名詞と通常本文が混在する範囲は、保護対象を含む子翻訳として扱います。複数色の場合も内部の各範囲を保持して組み立てます。子の固有名詞tokenは検証後に親の出現箇所へ対応付けるため、同じ名称が繰り返されても混線しません。名前直後の単独アポストロフィは日本語の助詞へ訳せますが、所有表現の完全な欠落、名前の改変、別の色範囲への移動は拒否します。引用符や記号だけのラベルにはこの判定を適用しません。

閉じた装飾範囲内の `\&` / `\&\` は、装飾を分断せず範囲内の区切りとして保持します。`&eSave Offset \&\ Side&r` 等は区切りを含む本文を別に翻訳し、外側の文には一つのtokenとして渡して開始・終了コードをアプリ側で復元します。記号の前後の本文や保護対象を検証するため、範囲全体は移動できても記号だけを範囲外や本文の端へ移すことはできません。`&a+&r` のような記号だけのラベルも、記号と装飾を一体で保持します。

FTB Questsで使われる `&dGem Case&f` のような「色付き本文を白へ戻す」範囲も、同じ行区間の各装飾範囲が自身の色を指定する場合は1単位として扱います。先頭の `&f` は通常の開始コードとして扱い、色を指定せず前の色を引き継ぐ装飾が混在する場合は固定配置を維持します。

`&aCreate a ...` のように改行・タブのない文字列の先頭から末尾まで掛かる単純な未閉鎖装飾stackは、可動tokenにせず検証後に原文と同じ先頭へ戻します。開始/resetの分断、別の改行segmentへの移動、孤立reset、複雑な未閉鎖装飾の移動は拒否します。

閉じた装飾範囲の後に `&dPlatinum Dust.` のような未閉鎖の末尾装飾がある場合、前の閉じた範囲だけを並べ替えられます。末尾が固有名詞と句読点だけならアプリ側でそのまま末尾へ復元し、通常の本文なら別に翻訳して末尾へ戻します。リセットコードは補いません。末尾との間で本文・固有名詞を移す応答や、色を継承するだけの装飾によって表示が変わる並べ替えは拒否します。

`&f1 Skill Point in &dMagic` のように、リセットで閉じず途中で色が変わる固定配置の本文も、範囲ごとに翻訳して原文順に連結します。装飾コードはAPIへ渡さずローカルで復元し、複数の色変更や太字等の継承でも順序を維持します。改行・タブをまたぐ範囲には適用しません。復元後は全文の装飾・固有名詞・本文を従来どおり検証し、欠落した子の翻訳や新しい装飾の混入は拒否します。

raw JSONの複数text componentをまたぐ固有名詞は、各componentの文字境界とstyleを保持します。既存訳の再利用時も同じ装飾範囲にあることを検証します。

通常文字列と単純な装飾付きtext objectからなるJSON配列では、通常本文を文単位で翻訳し、装飾付き要素は固定順序のtokenとして保持します。これにより `With `、`The `、`Using ` 等を孤立して翻訳せず、日本語に合わせて前後の通常文字列へ再配置できます。配列長・要素型・style・要素順は原文から復元し、元に文字列欄のない装飾間への挿入や文全体の本文欠落は拒否します。動的要素・hover・入れ子・改行・技術構文を含む場合や、通常本文をまたぐ固有名詞がある場合は、従来の要素単位の保守的な処理を使います。

通常文字列を挟まず隣接する装飾付き要素は、文側では一つのtokenにまとめます。例えば色の異なる `Gray` と ` Chalks` の間に、モデルが余分な文字を挿入する余地を作りません。各要素の本文翻訳・色・配列上の位置は個別に保持します。API用の参照情報は通常の警告ログの対象名から分離します。

英語から日本語への翻訳では、raw JSON内で独立した `and` / `, and ` が読点だけの訳になる場合も許可します。通常の本文や空の応答には適用せず、JSON構造と保護構文の検証は維持します。

## 応答の再試行とrefusal

保護復元の不一致は対象、key、原文ファイル、理由をログへ記録し、その項目だけ1度再試行します。バッチ応答の構造だけが壊れた場合は、原因項目を特定するため各項目を1件ずつ同じprotocolで再試行します。再度検証に失敗した場合はファイルを書きません。

APIが明示的なrefusalを返した場合は復元エラーとみなさず、バッチを停止して不要な項目別API呼び出しを行いません。

## 日本語のUnicode検証

翻訳先が日本語の場合、原文または固定した公式用語にないゼロ幅文字等の不可視文字、無関係な文字体系、未定義・私用・置換Unicode文字がAPIの本文へ新規混入していないことを確認します。検出時はその1件を再試行し、再発した場合は書きません。原文由来のMinecraft glyphは保持し、日本語以外のlocaleにはこの文字体系制限を適用しません。

## atomic writeとrollback

出力は同じディレクトリの一時ファイルへ完全に書き、検証後に置き換えます。API失敗や検証失敗で途中の翻訳ファイルを残しません。分割localeの複数ファイル更新が途中で失敗した場合は、更新済みファイルを元のbyte列へ戻します。

旧版直書きSNBTは、quest原本と言語資産を別々にstagingします。`config/ftbquests` 全体はコピーもリネームもせず、初回だけ実物の `quests` を `quests.bak` へリネームして新しい `quests` を配置します。どちらかの有効化に失敗した場合は変更済み出力を元へ戻します。

## 解析後の変更検出

翻訳開始時は解析済みのquestと固有名詞辞書を再利用し、固有名詞保護資産を再走査しません。解析後の翻訳元、確認後の出力先、staging中の旧版出力が外部変更された場合は書き込みを中止します。固有名詞資産は追加、削除、更新、リンク先変更を検出し、再解析を求めます。

変更確認でJARや言語ファイルの本文を再解析せず、解析時に記録した対象一覧とファイル状態を翻訳API呼び出し前と書き込み直前に照合します。rollback時も外部編集を検出し、その編集を上書きしません。

## 出力pathと固定上限

自動判定した出力pathの種類、拡張子、原文との衝突はOpenAI APIを呼ぶ前に再検証します。split localeでは `lang/<翻訳先locale>` 以外へ書きません。インスタンス探索でsymlink / junctionを再帰追跡せず、翻訳元や出力先が外部へ転送される場合も読み書きを拒否します。

API応答は16 MiBまでです。1件の文字列が設定したバッチ最大文字数を超える場合はAPI呼び出し前に停止します。Structured Outputs schemaは5,000 propertiesおよび110,000文字までとし、超える場合は1バッチ件数を小さくするよう案内します。
